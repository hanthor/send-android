# Implementation status

Send is an original Kotlin/Compose Matrix Android client with a conversation-first interface inspired by Android messaging patterns. It does not contain code or assets decompiled from Google Messages.

## Implemented paths

- Rust Matrix SDK `26.09.28` Android platform verifier bootstrapping before client creation; password, QR scan and SSO browser redirect sign-in; and a local SDK store (state, event cache, crypto) opened with a random 32-byte key that Android Keystore wraps (`SqliteStoreBuilder(data, cache).key(…)`). Until phase 8 the builder also called `sessionPaths`, which in this SDK replaces the store builder with an unkeyed one, so the store was written in plain SQLite; that is fixed, and a store from before the fix is wiped on restore (sign in again). The SDK's `StoreCipher` encrypts values and keys, not the SQLite file, and keeps the account's own Matrix ID readable in one crypto-store entry name (`ZZZSessionRestoreIntegrationTest` checks that room names and message text are not readable in any store file).
- Cold-start session restore: every sign-in path saves the SDK `Session` (access/refresh token, user and device ID, homeserver, OAuth data, sliding sync version) as JSON sealed with the same Keystore AES-GCM key, and a `ClientSessionDelegate` set on the `ClientBuilder` re-saves it whenever the SDK refreshes tokens. `restore()` rebuilds the client on the existing store and calls `Client.restoreSession` with the saved session; it returns false when nothing is saved. A store left without saved credentials is removed before a new sign-in (a new login is a new device), and sign-out clears the saved session with the store. `ZZZSessionRestoreIntegrationTest` simulates process death in-process (`MatrixRepository.close()` stops sync and releases every SDK object), relaunches `MainActivity`, and checks the same device ID is back, sync lists the rooms, an encrypted message sent before the restart still decrypts, a new message sends, and after sign-out `restore()` is false, the session prefs are empty and the relaunch shows the sign-in hero.
- SDK room-list updates show joined encrypted rooms with the latest-event snippet (`LatestEventValue`, "You: …" for own messages, Photo/Video/Voice message/file name for media), a Messages-style relative timestamp, and an unread badge from `RoomInfo` (`numUnreadMessages` / `notificationCount`). Room-list diff batches apply one at a time to an index-aligned mirror of the SDK list, so a burst of updates on a fresh sign-in cannot drop rooms; batches still in flight when a session closes are discarded. Opening a conversation, and each new arrival while it is open, sends a read receipt (`Timeline.markAsRead(READ)`) so the badge clears. Newly created encrypted DMs and groups are retained locally until sync publishes them. Unencrypted rooms are hidden and rejected by open/send/reaction/attachment operations.
- Encrypted text timeline send/receive, backward pagination, reactions, and room-keyed composer drafts that survive activity/process restoration. Conversation bubbles show localized event times, `Sending…`/`Sent`/`Not sent` for own messages (local echoes are shown immediately) and tap-to-reveal times. CI verifies Alice's encrypted message and 👍 reaction decrypt on Bob's independent SDK client after Bob joins the room.
- Conversation actions (phase 4, `ConversationScreen.kt`, `MessageActions.kt`, `MessageDecorations.kt`):
  - Long-pressing a message dims the rest of the screen and keeps the bubble lit (Messages' pattern): a rounded quick-reaction pill floats just above the bubble, with a button that opens the full emoji picker for any reaction (`Timeline.toggleReaction`), and a rounded menu card just below lists Reply, Forward, Copy, Edit (own text the SDK marks `isEditable`), Delete (own messages) and Info with leading icons. Both scale and fade in from the bubble on `SendMotion` springs; tapping outside or back dismisses.
  - Reply: swiping a bubble right past a threshold (resistance after it, a `GestureThresholdActivate` haptic, `SendMotion.spatialDefault` spring back) or the Reply action shows a "Replying to …" strip above the composer; sending uses `Timeline.sendReply`. Replies render the quoted sender and snippet (`MsgLikeContent.inReplyTo` → `EmbeddedEventDetails`, fetched with `fetchDetailsForEvent` when not loaded); tapping the quote scrolls to the original and flashes it, paginating back (up to 10 pages) when it isn't loaded yet.
  - Edit puts the text in the composer under an "Editing message" strip (the previous draft comes back afterwards) and sends `Timeline.edit` with `EditedContent.RoomMessage`; edited messages say "Edited" (`MessageContent.isEdited`). Delete asks "Delete message?" and redacts for everyone (`Timeline.redactEvent`); redacted events render as a muted "Message deleted" bubble. Copy puts the text on the clipboard. Info shows type, sender, sent time, status, edit state and who read it when.
  - Forward opens a picker of the other encrypted conversations (the list's rows); the message is re-sent there with `contentWithoutRelationFromMessage` (text, or media pointing at the original encrypted upload, without the reply relation) and that conversation opens.
  - Typing: the open conversation's draft drives `Room.typingNotice` (on while it has text, off when it is sent/cleared, after 5 idle seconds and on leaving); `Room.subscribeToTypingNotifications` (own user excluded, names from `memberDisplayName`) shows Messages' animated three-dot bubble.
  - Read receipts: the timeline tracks everyone's receipts (`EventTimelineItem.readReceipts`); under the newest own message "Sent" becomes "Read" in DMs or "Seen by N" in groups once someone's receipt (or later message) is at or after it.
  - Links: web URLs (`Linkify.WEB_URLS`) are tappable; the first http(s) link asks the homeserver for an OpenGraph preview (`Client.getUrlPreview`, cached per URL, og:image downloaded through the media cache) and shows a card with image, title, description and site. When the server has no preview (or previews are off) no card is shown. The URL goes to the user's own homeserver, as with any Matrix client's previews.
  - Media viewer (`MediaViewer.kt`): tapping a photo or video opens a full-screen viewer instead of another app — pinch/double-tap zoom with pan bounds for photos, a `VideoView` with play/pause, seek bar and times for videos, tap to hide the bars, Share (chooser through the `FileProvider`) and Save (MediaStore `Pictures/Send` or `Movies/Send`).
  - Emoji picker (`EmojiPicker.kt`): the composer's emoji button swaps the keyboard for a full picker — category tabs (recents, smileys, people, animals, food, travel, activities, objects, symbols, flags) from the bundled AndroidX `emoji2-emojipicker` lists, skin-tone/gender variants on long press, recents in preferences, and offline search by Unicode name (ICU `UCharacter.getName`, flags by country).
  - In-conversation search (⋮ → Search) filters the loaded timeline case-insensitively, highlights matches in the bubbles, shows "n of m" and steps between matches with older/newer buttons; stepping past the oldest loaded match loads older history. The SDK's `SearchService` (a client-wide local index) isn't used.
  - Star (long-press menu, Star/Unstar) writes the global account data event `dev.send.starred` (`{"rooms": {roomId: [eventId, …]}}`, `Client.setAccountData`), read back from the store (`Client.accountData`) at session start and whenever the Starred list opens, so stars follow the account to every session and survive a cold restore; a write this device made wins for 60 s until sync brings it back. Starred bubbles show a star by their time; ⋮ → Starred lists the conversation's starred messages (timeline copy, else `Room.loadOrFetchEvent`) with Unstar, and tapping one jumps to it (paginating back when needed). Per-room account data would fit better, but the FFI has no setter for custom room account data.
  - Select more (long-press menu) starts multi-select: taps add or remove bubbles, the top bar counts them and offers Copy (texts joined in thread order), Forward (each to the picked conversation) and Delete ("Delete N messages?", own messages only).
- Conversation list management (phase 5, `ConversationListManagement.kt`):
  - Swipe a row either way: it lifts onto a grey pill and follows the finger over a primary-blue track (Messages' colour on the comparison emulator) whose archive glyph grows in, with a `GestureThresholdActivate` haptic at 35% of the width; released past it (or flung) it springs off-screen (`SendMotion.spatialDefault`) and the room gets `m.lowpriority` (`Room.setIsLowPriority`, which also drops `m.favourite`); otherwise it springs back. A "1 conversation archived" snackbar offers Undo (unarchive, re-pin). Archived rooms leave the main list, stay archived when new messages arrive (tags don't change on activity) and notify as before unless muted. Account card → Archived lists them; swipe or select there to unarchive, tap to open (back returns to Archived).
  - Long-press a row: Messages' contextual top bar replaces the wordmark — close, the count, Pin/Unpin (`Room.setIsFavourite`; pinned rows sort first, keeping the SDK's recency order within each group, and show a pin icon), Archive, Delete, and ⋮ with Mute/Unmute (push rules, as the conversation menu), Mark as read/unread (`Room.setUnreadFlag`, plus `Room.markAsRead` for read; a marked-unread row is bold with a dot instead of a count, and opening the conversation clears the flag) and, for a single DM, Block. Selected rows get a tinted pill and a check mark in place of the avatar; taps add or remove rows; back or close ends selection.
  - Delete asks "Delete N conversations?" and then leaves and forgets each room (`Room.leave` + `Room.forget`), dropping its notification.
  - Block asks first (explains that the person can't reach this account on any device and that Spam & blocked undoes it), then `Client.ignoreUser`; DMs whose other member (the room's single hero) is ignored leave the list and the forward picker. Account card → Spam & blocked lists `m.ignored_user_list` (`Client.subscribeToIgnoredUsers`) with Unblock (`unignoreUser`).
  - List changes show at once: the repository overlays pending tag/flag changes and removals on the SDK list until sync reports them (or 60 s pass) and takes them back if the request fails.
- Attachments: the composer's ⊕ opens the system document picker and the gallery icon opens the Android Photo Picker; files are copied to the cache and sent with `sendImage` / `sendVideo` (bounds, duration and a generated JPEG thumbnail) or `sendFile`. With an empty draft the round action is hold-to-record voice: Ogg/Opus via `MediaRecorder` (runtime `RECORD_AUDIO`), a 40-sample amplitude waveform, sent with `sendVoiceMessage`; sliding away discards, and sliding up past the lock pill keeps recording hands-free with delete, stop (then play back) and send controls. The timeline renders photos/videos as rounded thumbnails (opened in the in-app viewer), voice/audio as play + waveform + duration (MediaPlayer), and other files as name + size; media is downloaded and decrypted with `Client.getMediaContent`, and other files open in other apps through a `FileProvider`.
- Create group: the New chat page's "Create group" pill collects Matrix IDs as chips plus an optional name and creates a private, encrypted, non-direct room inviting everyone.
- Account & E2EE safety: the home account button opens a Messages-style account card (display name, Matrix ID and avatar — tap for Profile — then Archived, Spam & blocked, Security, Settings, Sign out).
  - Sign out waits briefly for pending key-backup uploads, calls `Client.logout`, stops sync, closes every SDK object, and deletes the SDK/crypto store directory, media cache, session preferences and the Keystore-wrapped store key, then returns to the sign-in hero. It warns first when recovery isn't on for this device, and offers "Sign out on this device only" if the homeserver can't be reached.
  - Cross-signing is bootstrapped on first login (`ClientBuilder.autoEnableCrossSigning`). `Encryption` recovery, key-backup and verification states are surfaced as repository `StateFlow`s through `recoveryStateListener` / `backupStateListener` / `verificationStateListener`, plus `hasDevicesToVerifyAgainst`.
  - Security page: "Set up recovery" (`Encryption.enableRecovery`, waiting for existing room keys to upload, with progress) shows the recovery key once with Copy (sensitive clip) and an "I've saved my recovery key" confirmation; "Enter recovery key" / "Verify with recovery key" call `Encryption.recover`.
  - Emoji verification through `SessionVerificationController`: "Verify this device" (`requestDeviceVerification`, then `startSasVerification` once accepted), incoming requests from other sessions as an Accept/Decline prompt (`acknowledgeVerificationRequest` / `acceptVerificationRequest`), the 7 SAS emoji with names, They match / They don't match (`approveVerification` / `declineVerification`), cancel, and the cancel reason. Unverified sessions get a "Verify this device" banner on the conversation list when another verified session exists.
  - Undecryptable timeline events render as a muted "Waiting for this message…" bubble with an explanation from the SDK's `UtdCause` and, when verifying or entering the recovery key can help, an action that opens Security; the SDK swaps in the decrypted message when the key arrives.
- Notifications & push (`dev.send.matrix.notifications`):
  - Sources, all routed through `NotificationRouter`: the SDK's sync notification handler (`Client.registerNotificationHandler`, push rules evaluated on the decrypted event) while the process is alive — in the foreground or backgrounded; UnifiedPush messages; and a WorkManager `BackgroundSyncWorker` (every 15 minutes, network required) that restores the session and runs the SDK sync when no push distributor is registered. Events that arrive before their room key, and pushed event IDs, are fetched and decrypted with `NotificationClient` (`NotificationProcessSetup.SingleProcess` over the session's sync service, which runs the encryption sync itself when the app's sync isn't running). The router drops own events, unencrypted rooms, the conversation on screen in the resumed activity, events from before this device signed in, already-notified event IDs (sync vs push), muted rooms (`NotificationSettings.getUserDefinedRoomNotificationMode`, re-checked because synced push rules can lag), and events the account already read on any device (own read receipt timestamp).
  - Rendering (`MessageNotifier`): one `NotificationCompat.MessagingStyle` notification per conversation on the "Messages" channel, tagged with the room ID; senders are `Person`s keyed by Matrix ID with Send's avatar colour and initial as the icon; groups get the room name as conversation title. Each room gets a long-lived dynamic conversation shortcut (`ShortcutManagerCompat.pushDynamicShortcut`, `LocusIdCompat`, conversation category, person for 1:1s) linked from the notification, so it sits in the system's Conversations section. Lock screen: `VISIBILITY_PRIVATE` with a public version that only says "New message(s)". Tapping opens the conversation in Send (`MainActivity` consumes the intent into UI state, also from a cold start); opening a conversation cancels its notification and sets the activity's `LocusId`.
  - Actions: Reply (`RemoteInput`, semantic action REPLY) and Mark as read (semantic action MARK_AS_READ) go to `NotificationActionReceiver`, which enqueues an expedited `NotificationActionWorker`, so they work with no activity and from a cold process. Reply restores the session if needed, opens the room (encrypted rooms only, same check as every send path), sends through the timeline and waits for the send queue's `SentEvent` before adding the reply to the conversation notification; Mark as read sends a read receipt for the newest notified event (`Room.sendSingleReceipt`) and cancels the notification. Failures re-post the notification with "Reply not sent" / "Couldn't mark as read".
  - UnifiedPush (connector `3.3.5`): `PushRegistration` registers with the chosen distributor (the only installed one is picked automatically); `SendPushService.onNewEndpoint` discovers the Matrix gateway per the UnifiedPush spec (`GET <endpoint host>/_matrix/push/v1/notify` answering `{"unifiedpush":{"gateway":"matrix"}}`, else `https://matrix.gateway.unifiedpush.org/_matrix/push/v1/notify`) and calls `Client.setPusher` (HTTP pusher, `event_id_only`, pushkey = endpoint, app ID `dev.send.matrix`); a changed endpoint replaces the old pusher. `onUnregistered`, switching to background sync, and sign-out call `Client.deletePusher`. Push messages (`{"notification":{"event_id","room_id",…}}`) become an expedited `PushEventWorker` that fetches the event with `NotificationClient`. While no endpoint is registered the periodic background sync is scheduled; once one is, it is cancelled.
  - Settings → Notifications: whether Android allows Send to notify (with "Turn on notifications"), a link to Android's per-app notification page (channel sounds, pop-ups, lock screen), how messages arrive (push through a named distributor, connecting, the last registration error, or background sync), and a choice between installed distributors and "Background sync only". After the first sign-in Send explains notifications once before Android's `POST_NOTIFICATIONS` prompt.
  - Per-conversation notifications: the conversation ⋮ menu (and the details actions row) offers Mute (`NotificationSettings.setRoomNotificationMode(MUTE)`, which also clears its notification) / Unmute (`unmuteRoom`, back to the account default); details → Notifications picks All messages / Mentions only / Off (`setRoomNotificationMode` with `ALL_MESSAGES` / `MENTIONS_AND_KEYWORDS_ONLY` / `MUTE`, read back with `getRoomNotificationSettings`). Muted rows show a muted icon. The muted set comes from `getRoomsWithUserDefinedRules` and refreshes on the settings delegate.
  - `m.rtc.notification` events (ring or call notice), from any source, are routed once to `IncomingCalls.onIncomingCall` (see Calls below).
- Conversation details, profile and settings (phase 6, `ConversationDetails.kt`, `SettingsScreens.kt`, `SendSettings.kt`):
  - Details open from ⋮ → Details or by tapping the header's avatar/name (Messages' pattern): large avatar and name (DM: the other person's Matrix ID; group: "N people" and the topic), an actions row (Voice call, Video call, Search, Mute/Unmute), Notifications (above), and for groups Group name / Description (`Room.setName` / `setTopic`) and a camera badge on the avatar (`Room.uploadAvatar`, the picked photo scaled to 1024 px JPEG) — each shown only when the room's power levels let this account send that state event (`RoomPowerLevels.canOwnUserSendState`). Groups list People from `Room.members()` (store fallback `membersNoSync`): avatars, You first, roles from the SDK's suggested role (Admin/Moderator), invitees marked Invited; Add people (only with `canOwnUserInvite`) invites a Matrix ID (`Room.inviteUserById`). Tapping someone opens a profile sheet with Message (the existing encrypted DM via `Client.getDmRoom`, else a new one) and Block.
  - Media & files: the loaded timeline's attachments, newest first, as a four-tile strip on the page and a three-column grid (real thumbnails through the media cache, video badge, file/voice tiles); photos and videos open in the in-app viewer, other files in their app; the grid loads older history on request. Starred messages opens the phase-5 list. The encryption row says "End-to-end encrypted" with, in a DM, the other person's identity state from `Encryption.userIdentity` (verified, not verified, or changed since verification).
  - Bottom actions: Archive (`m.lowpriority`, back to the list), Block (DMs) and Delete conversation / Leave group (leave + forget), each confirmed.
  - Avatars: rooms (`RoomInfo.avatarUrl`, a DM's hero avatar otherwise), members and the account show their pictures (`Client.getMediaThumbnail`, cached) with the coloured initial as the fallback, in the list, the header, details and the account card.
  - Profile (account card): display name (`Client.setDisplayName`), photo (`Client.uploadAvatar`, `removeAvatar`), Matrix ID with Copy; the card follows `Client.subscribeToOwnProfile`.
  - Settings (account card → Settings, modelled on Messages settings' segmented list): Notifications, "Hear outgoing and incoming message sounds" (a synthesised rising pop when an own message finishes sending and a two-note chime when someone else's message arrives in the open conversation, silent when the ringer is off), Choose theme (Light / Dark / System default, driving `SendTheme` and the system-bar icon colours), Automatic previews (web link previews on/off: off stops `Client.getUrlPreview` calls), Security, Devices, Spam & blocked, Archived, About & licenses. Preferences live in SharedPreferences (`send_settings`). Bubbles and Suggestions are not offered (not implemented).
  - Devices: the account's sessions from `GET /_matrix/client/v3/devices` (this one first, then by last activity, with last-seen time and IP); Sign out on another session calls `POST /delete_devices` and answers user-interactive auth with the account password (`m.login.password`), or opens the homeserver's fallback page for other stages and retries with the session; accounts on an OAuth server go to the account page (`Client.accountUrl(DeviceDelete)`). The FFI has no device-list or delete call, so these use the client-server API with the session's access token.
- Motion (phase 7, `MotionComponents.kt`, `SendMotion.kt`):
  - "Start chat" is an M3 extended FAB that collapses to its 56dp icon while the list scrolls down and expands scrolling up or at the top, on MDC's public `m3_extended_fab_change_size_{collapse,expand}_motion_spec` values (the resources Messages ships): width/padding over `motionDurationMedium4` (400ms) on the emphasized easing; the label fades out after 50ms over 100ms when collapsing and in after 100ms over 200ms when expanding.
  - List items use `animateItem` on SendMotion tokens (spatial-default placement spring, effects fades): conversation rows slide when a pin, archive, delete or new message reorders the list; Archived, Spam & blocked and Starred rows likewise; in the timeline older bubbles slide up as a new one arrives. Timeline rows are keyed by the SDK's unique timeline item ID (`TimelineItem.uniqueId`), so a local echo turning into the remote event keeps its row instead of replacing it. At the newest message, arriving bubbles and typing dots scroll into view.
  - Bubble entry: a message that arrives while the conversation is open (newer than its opening, once per item) enters: own bubbles rise 64dp from the composer on the spatial-default spring while fading in; incoming ones fade in and grow from 80% about their bottom-start corner. Loaded and paginated history doesn't animate.
  - Predictive back (`android:enableOnBackInvokedCallback`, Compose `PredictiveBackHandler`): leaving a conversation for the list, and closing Details, Media & files, Starred, Archived, Spam & blocked and the Settings pages (Settings, Devices, Profile), the leaving screen follows the gesture like the system's in-app predictive back — down to 90% scale, shifted toward the swipe with an 8dp margin, rounded corners — springs back if cancelled, and on release leaves with SendMotion's close transition from where the gesture left it. In a conversation, back first closes the long-press menu, multi-select, emoji panel, search, locked recorder, edit and reply, as before.
  - Shared elements: the top-level screens sit in a `SharedTransitionLayout` (`SendScreenHost`); a conversation row's avatar (`sharedElement`) and name (`sharedBounds`, the two text styles cross-fade) travel into the conversation header on open and back into the row on back (key: room ID), on the spatial-default spring alongside the 300ms open/close transition. A predictive back release starts the return from the scaled screen.
  - Swipe-to-reply and swipe-to-archive share `SwipeThreshold` (the platform's `GESTURE_THRESHOLD_ACTIVATE` crossing the threshold and `GESTURE_THRESHOLD_DEACTIVATE` crossing back) and settle on `SendMotion.swipeSettle` (spatial default).
- Calls (MatrixRTC through Element Call Android `0.1.0-rc.7`, `NativeMatrixCallSession`):
  - Transport discovery: rc.7 reads the MSC4143 endpoint with an unauthenticated request, which Synapse rejects; Send wraps Element Call's Matrix transport so the lookup is answered by `Client.discoverRtcTransports()` (authenticated endpoint, then well-known `rtc_foci`).
  - Incoming: a RING becomes a `NotificationCompat.CallStyle.forIncomingCall` notification on the "Calls" channel (ringtone, vibration, `FLAG_INSISTENT`, `CATEGORY_CALL`, caller `Person` with Send's avatar, timeout at the ring's expiry) with a full-screen intent to `IncomingCallActivity` (shows on the lock screen and turns the screen on; Messages-style avatar, name, red Decline / green Answer). Without Android 14+ full-screen access the ring is a heads-up; Settings → Notifications links to the setting. A watcher stops ringing when the user's own decline arrives from another device (`subscribeToCallDeclineEvents`), the user joins on any device or the caller leaves (`activeRoomCallParticipants` / `hasRoomCall`), or the ring expires. Answer opens `MainActivity` (asking to dismiss the keyguard), which joins the room's session with `ElementCallController.startCall`; a call in another room is hung up first. Decline stops ringing at once and sends `m.rtc.decline` (`Room.declineCall`) from an expedited worker. Group "call started" notices don't alert.
  - Outgoing: the header's Video call / Voice call start Element Call, which rings the other side of a DM itself (MSC4075 RING with the call intent); Send follows that ring, shows "Calling <name>…" over the call screen, and on the other side's decline (`CallDeclineListener`) hangs up with a "Call declined" snackbar. Element Call asks for the camera when a video call starts.
  - Timeline: call notifications render as centred rows — "Missed voice call" (Call back in DMs), "Voice call · 2:31" (duration from the call-membership state events between this call and the next), "Voice call · No answer", "Call declined", "Voice call in progress" (Join). List snippets describe calls.
  - Running calls (`hasRoomCall`, `activeRoomCallParticipants`, consensus intent) show a call icon on the list row and a "Voice call in progress · N people" banner with Join in the conversation.
  - New DMs use `trusted_private_chat` so either person's ring (a room mention) passes push rules; new groups let every member publish call memberships.
- Share target (phase 8, `ShareTarget.kt`): an exported, translucent `ShareActivity` receives `ACTION_SEND` / `ACTION_SEND_MULTIPLE` (text, images, video, audio, any file), copies the text and every readable stream into the cache before the sender's grant lapses (Send's own provider and `file://` URIs are refused) and hands the staged share to `MainActivity`, also on a cold start or before sign-in. The picker is the Forward picker (encrypted, non-blocked conversations only); a confirmation ("Send to <name>?") shows the text, file names and photo thumbnails, and nothing is sent until the user confirms. Sends go through the encrypted-only paths (`sendText`, then `sendFileAttachment` per file), the conversation opens and the staged copies are deleted. Conversation shortcuts carry `dev.send.matrix.category.SHARE_TARGET` (declared in `res/xml/shortcuts.xml`), so recent conversations appear as direct-share targets; a share with `EXTRA_SHORTCUT_ID` goes straight to the confirmation when that room is still an encrypted joined room.
- Large screens (phase 8, `AdaptiveLayout.kt`): windows at least 600dp wide and 480dp tall show the conversation list (40% of the width, 280–400dp) beside the open conversation; the open row is highlighted and announced as selected, an empty detail pane shows a quiet placeholder, back closes the conversation and stays two-pane, Details opens in the detail pane and Settings/Profile/Devices/Archived/Blocked open full width. The host stays in the composition across layout changes, so fold/unfold (no activity recreation) keeps the open conversation, draft, scroll position and keyboard. Phones in landscape stay single-pane.
- Accessibility and dark theme (phase 8, `docs/accessibility.md`): icon-only controls have labels and roles, rows merge their state ("2 unread", "Pinned", "Muted", selected), swipe and long-press gestures have TalkBack equivalents (Archive/Unarchive and Select on rows, Reply on bubbles, "Record hands-free" on the voice button), touch targets are at least 48dp (one-line bubbles rely on Compose's touch-target expansion), top bars, the header and the composer reflow at large font scales instead of clipping, and every colour pair meets WCAG AA (table in `docs/accessibility.md`; avatar fills were darkened from 1.55–3.69:1 to 4.65–5.42:1). Both colour schemes define every Material token in Send's blue family (previously several fell back to Material's purple); the remaining fixed colours sit on always-dark surfaces (media viewer, call buttons).
- Release (phase 8, `app/build.gradle.kts`, `app/proguard-rules.pro`, `.github/workflows/release.yml`): versionName/versionCode come from the `v*` tag (`MAJOR*1000000 + MINOR*10000 + PATCH*100 + rc number, or 99 for a final release`); the release build is R8-minified with resource shrinking, keep rules for JNA/UniFFI (`com.sun.jna`, `Structure` field order, the SDK's and RTC core's `native` bindings), libwebrtc's JNI half and WorkManager workers, and per-ABI APKs (arm64-v8a, armeabi-v7a, x86_64 + universal, native libraries compressed) plus an AAB. A tag push builds, signs (the `SEND_KEYSTORE_*` secrets, or a throwaway key with `-UNOFFICIAL-ci-signed` artifacts when they're absent), verifies signatures, versions and ABIs, runs the whole instrumentation suite on a `minified` build type with the release R8 rules, and publishes a GitHub Release with the APKs, AAB, `mapping.txt` and SHA-256 sums. The release build only allows HTTPS; the plain-HTTP CI homeserver is a debug/minified-only resource flag.
- Store listing and privacy (phase 8): `fastlane/metadata/android/en-US` (title, short and full description, changelogs `10001`/`10002`, icon, feature graphic, six phone screenshots and a tablet screenshot captured in CI by `StoreScreenshotsTest`), an original adaptive launcher icon with a themed (monochrome) layer (source `docs/brand/send-icon.svg`), and `PRIVACY.md`, also bundled and shown in-app from About & licenses → Privacy policy (a unit test keeps the copies identical).
- Instrumentation covers login validation, local Synapse sign-in, encrypted direct-room creation, encrypted message send and local timeline rendering, cross-device delivery/decryption and reaction receipt on Bob's second client, photo and voice-message delivery to Bob plus SDK media download of the encrypted photo, list snippet and unread badge raise/clear, UI group creation, new-chat/group validation, attachment/voice rendering, legal notices, reaction selection, and the account/security fixtures (account card, sign-out warning, recovery key shown once, unverified-device options, 7-emoji SAS screen, incoming-request prompt, undecryptable bubbles, verify banner). `ZZAccountSecurityIntegrationTest` runs the E2EE flow end to end against Synapse: Alice sets up recovery in the UI and reads the key; sends an encrypted message and waits for key backup; a second Alice SDK client (fresh store, password login) requests verification, the app accepts the prompt, both sides show the same 7 emoji and confirm; the second client recovers with the key and decrypts the earlier message from key backup; Alice signs out from the account card (sign-in hero shown, `restore()` false, store directory gone); signing in again shows the verify banner and a "Waiting for this message…" bubble, whose action leads to "Verify with recovery key", after which the message decrypts in place. GitHub Actions runs assemble, unit tests, lint, and Android-emulator instrumentation; successful runs upload full-resolution screenshots and the debug APK.

## Known implementation limits

- Calls: AndroidX Core-Telecom isn't used, because Element Call owns call audio (audio-device controller, audio focus and its microphone/camera foreground service), which a self-managed Telecom call would also claim; ringing is notification-only. A ring nobody answers or declines on any of the user's devices (expired, or the caller gave up) leaves a "Missed voice/video call" notification on a "Missed calls" channel with Call back and Message; opening the conversation clears it. DMs created before this change (`private_chat`) don't alert their creator when the invitee rings, because the ring's room mention needs notification power. Media is not verified in CI (see below).
- Encrypted 1:1 room creation from a Matrix user ID is implemented. Conversation bubbles, widgets, Android Auto, dictation, text-to-speech, and AI features remain roadmap items in `ANDROID_INTEGRATIONS.md`.
- Notifications: FCM isn't included (no Firebase project), so instant push needs a UnifiedPush distributor; without one, messages arrive while Android keeps the process alive (frozen cached apps don't sync) and through the 15-minute background sync. Invites don't notify yet. End-to-end delivery through a real distributor (e.g. ntfy) isn't automated: the CI emulator has no distributor app, and Synapse in Docker can't reach a gateway on the emulator. CI covers endpoint→pusher registration against Synapse and the pushed-event path from a closed session; the distributor transport is left to device testing.
- CI provisions two Synapse demo accounts and verifies Alice-to-Bob encrypted delivery/decryption and reaction receipt on Bob's independent client, plus recovery, SAS verification and key-backup restore across Alice's devices. The app's outgoing "Verify this device" request is covered by fixtures and shares the SDK path the second client drives in CI, but is not itself run end to end (the CI device being verified is the SDK client, not the app). Pre-existing remote room-list population is not verified. MatrixRTC signalling is verified against Synapse + lk-jwt-service + LiveKit, but not media: Bob is an SDK client with a call membership and no media stack, and Alice's answered call stays in `ConnectingMedia`. The full-screen ringing screen over a locked screen, ringtone and vibration aren't exercised either (CI's screen is unlocked, so the ring shows as a heads-up). The CI emulator cannot resolve `matrix.reilly.asia`, so remote SSO/production login is also unverified.
- Element Call is a release candidate; upstream APIs may change. This repository uses its documented minimum Rust SDK version `26.09.26`; the pinned stable SDK `26.09.28` meets that floor, with build/runtime compatibility still to verify.

## Build and delivery

- Public repository: https://github.com/hanthor/send-android
- GitHub Actions provisions Gradle `9.6.0` through the committed Gradle wrapper and Android API 37; builds/tests/lint run in GitHub CI, not locally, per request.
- CI uploads the debug APK (`Send-debug-APK`), reports (`Send-Android-Test-Results`), and full-resolution fixture/live Synapse screenshots (`Send-UI-Screenshots`) for 30 days. The checked-in walkthrough PNGs are generated by that workflow; live screenshots show a locally created encrypted conversation and an SDK-sent message.
- Releases: pushing a `v*` tag runs `.github/workflows/release.yml` (build and sign per-ABI APKs and an AAB, verify, run the instrumentation suite on the R8 `minified` build, publish a GitHub Release with `mapping.txt` and SHA-256 sums). Without the `SEND_KEYSTORE_*` secrets the artifacts are signed with a key generated in the job and named `-UNOFFICIAL-ci-signed`; see `DEVELOPMENT.md` → Releases for what the owner adds. Store listing text and graphics live in `fastlane/metadata/android/en-US`.
